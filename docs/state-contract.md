# State and parameter contract

Version 10 host-state foundation, 15 November 2026. The JSON Schemas in `schemas` describe planned kit and project records; they are not yet runtime serializers.

## Host parameter IDs

- `master.gain.v1`: linear gain, normalized 0 to 1, default 1.
- `pad.01.level.v1` through `pad.16.level.v1`: linear level, normalized 0 to 1, default 1.
- `pad.01.mode.v1` through `pad.16.mode.v1`: choice 0 one-shot (default), 1 gate. In gate mode, note-off fades the oldest held voice for that pad over 5 ms.
- `pad.01.choke.v1` through `pad.16.choke.v1`: integer group 0 (off, default) through 4. A new note or audition fades existing voices in its nonzero group over 5 ms.
- `pad.01.mute.v1` through `pad.16.mute.v1`: Boolean, default false. Muted pads reject new notes and audition requests. Active voices fade over 5 ms when muted.
- `pad.01.solo.v1` through `pad.16.solo.v1`: Boolean, default false. If any pad is soloed, all soloed and unmuted pads can play; other pads reject new triggers and their active voices fade over 5 ms. Mute takes precedence over solo.
- `pad.01.voices.v1` through `pad.16.voices.v1`: integer 1 to 4, default 4. One voice provides mono retrigger; the replaced voice enters a 5 ms fade tail.
- `pad.01.velocity.v1` through `pad.16.velocity.v1`: choice 0 soft (square root), 1 linear (default), 2 hard (square). UI audition is always full velocity.
- `pad.01.coarse.v1` through `pad.16.coarse.v1`: integer -24 to +24 semitones, default 0.
- `pad.01.fine.v1` through `pad.16.fine.v1`: -100 to +100 cents in 0.1-cent steps, default 0. Playback uses the sum of coarse and fine offsets. A new voice starts at the requested resampling ratio; an active voice moves toward a changed ratio with a 10 ms time constant. Pitch and duration change together. The editor's semitone snap rounds the combined offset to the nearest semitone and sets fine tuning to zero. Scale quantization is optional and is not implemented.
- `pad.01.amp.attack.v1` through `pad.16.amp.attack.v1`, and the corresponding `decay` and `release` IDs: linear 0 to 10 seconds in 0.001-second steps, default 0. `pad.NN.amp.sustain.v1`: linear level 0 to 1 in 0.001 steps, default 1. Attack and decay are linear ramps measured in host samples. The values are captured when a voice starts; host automation changes following triggers. UI audition follows one-shot behavior. With a positive release, a one-shot begins its release before the edited sample boundary and clamps the ramp to the remaining duration. Gate note-off starts release from the current envelope level. A zero release uses the existing 5 ms safety fade on gated note-off. Choke, mute, transport stop and stolen voices retain their independent 5 ms anti-click fade. The edit fade multiplies the ADSR envelope, so an edited fade remains audible with ADSR enabled.
- `pad.NN.filter.mode.v1`: choice Off (default), Low-pass, High-pass, Band-pass. `pad.NN.filter.cutoff.v1`: 20 to 20,000 Hz, default 20,000 Hz, with a 1,000 Hz centre in normalized host mapping. Effective cutoff is capped at 45% of the current host sample rate. `pad.NN.filter.resonance.v1`: Q 0.5 to 10, default 0.707. `pad.NN.filter.depth.v1`: bipolar -48 to +48 semitones, default 0; the independent filter envelope scales this offset from zero at envelope level 0 to full depth at level 1. `pad.NN.filter.attack.v1`, `decay`, `release`: linear 0 to 10 seconds in 0.001-second steps, default 0. `pad.NN.filter.sustain.v1`: 0 to 1, default 1. Filter mode and envelope values are captured at voice start. Cutoff, Q and depth follow host automation on active voices through eight-sample target updates and 5 ms coefficient smoothing. Each voice has separate stereo state-variable filter integrators. Filter-envelope release starts at gated note-off or, for one-shots with positive release, near the edited sample boundary. The filter is fully bypassed in Off mode. The filtered per-voice signal is bounded to ±8 before voice gain, with non-finite integrators reset to zero.
- `pad.NN.lfo.destination.v1`: Off (default), Pitch or Filter Cutoff. `pad.NN.lfo.shape.v1`: Sine (default), Triangle, Square or Saw. `pad.NN.lfo.rate.v1`: 0.05 to 20 Hz, default 1 Hz, 0.001 Hz steps with a 2 Hz normalized centre. `pad.NN.lfo.depth.v1`: 0 to 24 semitones, default 0, 0.1 semitone steps. `pad.NN.lfo.phase.v1`: Reset Each Note (default) or Free Running. Pitch and cutoff use bipolar semitone offsets around their base settings. Destination, shape and phase mode are captured at note onset. Rate and depth follow live parameter changes; depth and waveform are smoothed, while pitch uses its 10 ms ratio smoothing and cutoff uses its 5 ms coefficient smoothing. LFO targets update every eight samples. Reset mode starts each voice at phase zero. Free mode uses a per-pad clock that advances even between notes and resets on engine preparation. There is no host tempo sync.
- Future pad IDs follow `pad.NN.<semantic-name>.vM`, where NN is 01 to 16 and M is a semantic version integer. Grid slot and MIDI note stay separate: slot 01 defaults to note 36 and slot 16 to note 51. A swap exchanges pad content, not slot ID or MIDI note.

The `.v1` suffix is part of the immutable host ID. Do not rename or repurpose an ID after release. Add a new ID and a migration when semantics change. Parameter range, display unit, smoothing, and ownership for each new control must be documented before it is exposed to a host.

Phase 5 float parameter text uses three decimals for envelope times and sustain, integer hertz for filter cutoff, two decimals for resonance and LFO rate, and one decimal for semitone depth. Seconds, hertz and semitone units are also supplied through host parameter labels. The editor reads the same host-owned parameter values in bounded snapshots; it does not persist a separate parameter model. For amplitude, filter and LFO edits, the UI displays the pending value immediately and serializes native writes per panel. A 16 ms minimum interval and latest-value replacement per field bound dense slider traffic. Native snapshots confirm accepted values and propagate host-originated changes to visible controls.

## Current host serialization

The binary host state starts with the four-byte magic `HR10`, format version 10, and a length-prefixed `HYPERREAL_STATE` JUCE ValueTree with `schema_version = 10`. It then stores 16 fixed-order pad records. Each record has a presence flag and, when loaded, a sample name, source rate, channel count, frame count, decoded float data, four source-frame edit coordinates and one reverse flag. Edits do not alter embedded source audio. No source path is required to restore the current sound. Import and restore accept finite positive source rates up to 384 kHz. The reader validates all samples and the 512 MB aggregate limit before publishing any pad. `HRP9` retains filter and amplitude settings and defaults LFO parameters; `HRP8` retains amplitude ADSR and defaults filter and LFO parameters; `HRP7` retains edits and tuning and defaults amplitude, filter and LFO parameters; `HRP6`, `HRP5`, `HRP4` and `HRP3` retain all 16 samples with default full-region edits; Phase 2 `HRP2` states are read as pad 1 plus 15 empty pads; Phase 1 parameter-only ValueTrees remain readable. New parameters use their defaults when absent from older states loaded into a fresh instance. Unsupported or malformed state is ignored without replacing active samples.

The UI snapshot uses bridge schema version 2, with selected pad index 0 to 15 and 16 pad status/name records plus the selected pad level, mode, choke, mute, solo, voice limit and velocity curve controls. Each pad status record also reports mute, solo and a monotonically wrapping MIDI note-on counter. The editor compares counters between polls and flashes the receiving pad separately from local audition. Activity counters are transient and not saved in host state. Setting mode, choke, mute, solo, voice limit and velocity curve uses bridge command version 3. Selection is an editor control and is not yet persisted. LOAD and AUDITION target a pad; audition is one-shot regardless of pad mode. With default amplitude settings, a one-shot holds full amplitude until the final 5 ms of its sample, then fades to zero at the last source frame; a shorter sample fades over its available frames. Gate release, choke and voice stealing can end it earlier. The voice pool holds up to the configured one to four voices per pad and 64 globally, plus 64 bounded release tails for interrupted voices. One-shot note-off is ignored. MIDI all-notes-off and all-sound-off fade active voices over 5 ms. A note-on with zero velocity is treated as note-off. The oldest voice in a pad enters a 5 ms fade tail when its limit is reached. If all 64 tail slots are occupied, the selected old voice releases in place and the incoming note is dropped, preserving an anti-click fade within bounded storage. Note-off releases the oldest held voice for the matching pad and MIDI channel. Same-offset MIDI events are processed in buffer order; the later trigger wins a choke group. When a host playhead reports a transition from playing to stopped, the processor requests a 5 ms release of all active voices. If playhead state is unavailable, MIDI all-notes-off and engine preparation remain the reset paths. Cubase Stop silenced an active sample, but that audible check could not distinguish the two stop mechanisms.

WebView file drops use bridge command version 5: begin with pad, name and byte size; append validated Base64 chunks no larger than 64 KB decoded; finish only after the declared size is received. The native editor limits a transfer to 128 MB, and the worker decodes the resulting memory buffer. No source path or temporary file is required. Right-click menu actions and single-click audition use the existing bridge commands. Pad copy, paste, swap and clear use bridge command version 4. The bridge requires a confirmed flag for paste, swap and clear; the editor presents a second confirmation step. Copy includes the sample and current level, mode, choke, mute, solo, voice limit and velocity curve settings. Paste checks the 512 MB active kit limit. Swap exchanges those settings and sample buffers, while MIDI notes stay with the grid slots. Clear resets settings to defaults. Pending imports for affected pads are invalidated. Existing voices can finish using their original sample. Clipboard data is temporary and excluded from host state.

Phase 4 adds trim start/end, fade lengths and reverse to the selected-pad snapshot, plus source frame count, sample revision and transient playback frame. Bridge command version 6 applies an edit or fine-cent value after validating the pad and finite coordinates; coarse semitones use the integer parameter command version 3. Cached waveform min/max summaries are requested by pad and resolution through a version 6 read command. They are generated when media is decoded and are not host state. The Canvas shows the source peak trace and an approximate fade-scaled edit preview without sending raw audio continuously. Estimated playback duration is selected source frames divided by source sample rate and tune ratio. Copy/paste/swap carry edits with the sample and carry both tune parameters with pad settings. An edit replaces only metadata; new triggers use it immediately, while existing voices finish against their original edit snapshot. An overlong fade is clamped to the selected region; a one-frame region is valid. On a one-frame region, either nonzero fade starts or ends at zero and silences that frame; set both fades to zero to hear it. Overlapping fades multiply their gains. Forward and reverse playback use the same region-relative fades. Linear interpolation is used for resampling and is not band-limited, so strong upward transposition may alias.

The Phase 4 editor applies each valid trim, fade or reverse change when it is made and coalesces rapid drag updates into ordered native commands. Commands can carry the current sample revision; the engine rejects stale commands after a sample replacement. Waveform frame, tune, zoom and view values now use rotary controls with numeric readouts, fine Shift-dragging and keyboard adjustment. The editor has no Apply, Revert Draft or Full Sample controls. Escape or a cancelled marker drag restores that drag's starting edit through the same ordered native commands. Fade lines are diagonal from the bottom of the trim boundary to a draggable tip at the top. The transient `playbackSpeed` snapshot field reports signed source frames per second for the active voice; a separate UI Canvas interpolates the progress cursor between snapshots. The source audio remains unchanged and previously sounding voices retain their edit snapshot.

Phase 5 adds selected-pad amplitude ADSR values in the existing snapshot and a bridge command version 8 for setting one amplitude parameter. Filter mode, cutoff, resonance, bipolar depth and independent filter ADSR use bridge command version 9. The custom editor displays host-backed values and schematic envelope graphs. LFO destination, shape, rate, depth and phase use bridge command version 10. The editor shows a waveform preview. Copy, paste, swap and clear include these parameters.

The snapshot includes transient `masterPeakLeft`, `masterPeakRight`, `masterClipLeft` and `masterClipRight` readings from the post-gain stereo output. They are meter display data, not host parameters or saved state. Each channel's peak decays with a 0.45-second time constant; a block at or above 0 dBFS holds that channel's clip flag for 0.65 seconds. Each of the two Master Gain LED rows uses peak thresholds of 0.02, 0.04, 0.08 and 0.16 (green), 0.32 and 0.5 (amber), and 0.707 and 1.0 (red). The final red LED also follows its channel's held clip flag.

## Planned portable data

A pad record contains its fixed slot, source sample reference or bundled content identifier, non-destructive edit coordinates, mode, tuning, voice and choke settings, envelope/filter/LFO settings, mute/solo, level/pan, and bus assignment. A kit contains 16 pad records and a versioned manifest. Factory kits are read-only; user kits are stored in a separate writable location. Portable bundles must use relative paths, reject path traversal, and preserve original media. A project state must capture or collect referenced media robustly enough to recall after source files move.

Each schema has an integer `schemaVersion`. Keep readers for supported old versions. Reject unsupported future versions without partially applying data. File decode, archive validation, and serialization run off the audio callback. Prepared changes become active at safe processing boundaries.
